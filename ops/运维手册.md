# 采集链运维手册

> 这条链每天 09:23 自己跑一次。**电脑重启后它会自己回来** —— 但那是 2026-08-15
> 才修好的，在那之前不会（原因见文末「曾经踩过的坑」第 1 条）。
>
> 这份文档回答四件事：它是什么、重启后怎么办、怎么看它有没有在干活、坏了怎么修。

---

## 一、它是什么：一条链，七段

```
launchd（每天 09:23）
   └─ scripts/tick.sh
        ├─ ① watch.mjs --due          抓到期的源 → 写 data/snapshots/
        ├─ ② extract.mjs              有变化才调模型 → 写 data/inbox/（唯一花钱的一步）
        ├─ ③ fresh.mjs                保鲜巡检（仓库数字 / README 漂移 / 外链）
        ├─ ④ requote.mjs --report     回查引文 → 写 data/requote-report.md
        ├─ ⑤ version-sentry.mjs --json 版本哨兵 → 写 data/version-sentry.md
        ├─ ⑥ todo.mjs --notify        汇总成 data/TODO.md + 发通知
        ├─ ⑦ alert.mjs --push         挑在架的快讯 → data/alerts.json + 推一条飞书
        └─ ⑧ git commit               署名 atlas-watch[bot]
```

**⑤ 版本哨兵是 2026-09-10 补的，补的是这条链上一个整整一个月的窟窿。**

那天负责人报了三条我们「不知道」的模型更新，查下来最难堪的不是漏抓：
`anthropic-models` 09-02 那次抓取就写着 Claude Fable 5.1、`openai-models` 09-09 那次就写着
gpt-6-astra，而库里还记着 Fable 5 和 GPT-5.6。**抓到了，只是没有任何一步会说「这条要写回」。**

三条既有检查各自都够不着：① 只报「这个源变了」，一天几十个源都在变；
② 从 08-08 起因为缺 `MINIMAX_API_KEY` 连跳 34 天，而跳过只是日志里一行 echo；
④ 确实发现了「Claude Fable 5 is generally available」这句在页上没了，
然后被 ⑥ 归进标着 `machine: true` 的「机器状态 · 不用你判断」那一摞 ——
**一次真的换代，被归成了机器噪音。**

所以 ⑤ 的输出**永远进「该你拍板」，不许进「机器状态」**；
而 ② 这类整步被跳过的情况，现在由 `scripts/stamp.mjs` 写进 `data/pipeline.json`，
⑥ 会把「已经连着 N 天没跑」摆到人面前。

**④ 和 ⑤ 是两件事，别混：** ④ 报的是**我们自己要干的活**（收件箱里躺着几条待审），
⑤ 报的是**世界变了、而且读者今天就该知道**。前者只给自己看，后者同时上站内横幅、RSS 和飞书。

**三条纪律，改任何一段都不能破：**

1. **机器只写快照、报告、收件箱，绝不碰 `data/atlas.json`。**
   「世界变了」和「我们认定它变了」是两件事，后者要人审（§59.3 的黄/红通道）。
2. **提交署名 `atlas-watch[bot]`**，在 `git log` 里和人工提交一眼分得开。
3. **失败不静默。** 抓不到、抓到空壳都进日志与报告 ——
   **一个长期抓不到的官方源本身就是信息**：那家没有可 diff 的公开入口，
   这正好解释了它名下的格子为什么质量最差。

## 二、电脑重启之后

### 正常情况：什么都不用做

plist 已软链到 `~/Library/LaunchAgents/`，登录时 launchd 会自动读它。
**笔记本合盖睡过头也不会漏**：`StartCalendarInterval` 在错过触发时间后
会在下次唤醒时补跑一次（这是当初选 launchd 而不是 crontab 的唯一理由）。

### 三十秒自检

```bash
cd ~/projects/xiamimate/xiamimate-ai-atlas

# 1. 任务在不在（有输出 = 在）
launchctl list | grep xiamimate

# 2. 上次什么时候跑的、跑成了没有
tail -20 data/watch.log

# 3. 待办有几条
head -3 data/TODO.md
```

三条都正常就不用管了。**第 1 条没输出**才需要下一节。

### 如果任务不见了

```bash
cd ~/projects/xiamimate/xiamimate-ai-atlas

# 重新装（软链 + 装载，可重复执行，装过了也不会坏）
ln -sfn "$PWD/ops/com.xiamimate.atlas-watch.plist" \
        ~/Library/LaunchAgents/com.xiamimate.atlas-watch.plist
launchctl bootout   gui/$(id -u)/com.xiamimate.atlas-watch 2>/dev/null
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.xiamimate.atlas-watch.plist

# 立刻踢一次，验证端到端能跑
launchctl kickstart -k gui/$(id -u)/com.xiamimate.atlas-watch
tail -20 data/watch.log
```

⚠️ **用软链不用复制。** 复制过去的话，以后改 plist（比如换时间）
要记得再复制一次 —— 那种「要记得」的东西迟早会忘。软链让 plist 继续跟着 git 走。

## 二之二、审阅台 —— **所有操作只从这一个地方走**

负责人 2026-08-18 定死：「所有的操作，我只从本地审阅台一个地方处理。」

在那之前，待办通知里每一摞后面跟一条**不同的命令** —— 七摞七条。
人不会每天开七次终端，于是通知照发、待办照攒，
而这正是当初建 `todo.mjs` 想解决的毛病，只是换了个地方犯。

现在审阅台三个标签，通知与飞书都只给这一个地址：

- **待办** —— 当天所有摞的总览（和 `data/TODO.md` 同一段代码算出来的）。
  这一页还能**直接把脚本跑起来**，跑完自动重算；四份报告原文也在这页点得开。
- **收件箱** —— 抽取器捞出来的候选事实，判「这条对不对」（通过 / 驳回）
- **引文回查** —— `requote.mjs` 找出的「引文和它署的源对不上」，判「这句该归到哪」：
  改署名 / 换这个源的抓法 / 认了它不是逐字原文

### 怎么开

点通知就行（会自己拉起来）。手动：

```bash
launchctl kickstart gui/$(id -u)/com.xiamimate.atlas-station   # → http://127.0.0.1:8230
npm run station                                                # 或者前台跑，看得见日志
```

关掉：`launchctl kill TERM gui/$(id -u)/com.xiamimate.atlas-station`

### **不做开机自启，这是有意的**

2026-08-15 负责人拍板「保持手动就好」——
它和采集器不一样：**它能写 `atlas.json` 并直接提交 git**。
一个能改库的服务常驻后台还随开机自启，风险和收益不成正比。

`ops/com.xiamimate.atlas-station.plist` 里 `RunAtLoad` 是 **false**，
装上它不等于自启 —— 它只是**待命**，谁需要谁 kickstart。
之所以要走 launchd 而不是让通知那个 app 自己 fork 一个后台进程：
app 一退出，LaunchServices 会把整个进程组一起收走，审阅台跟着没（2026-08-18 实测）。

### 改了什么 —— **多选，一次提交**

台上的活都会改文件，而**唯一会提交的是 `tick.sh`，且它只提交自己那几份**。
所以点完一圈之后工作区就一直脏着 —— 2026-08-19 那次 `atlas.json`、`fresh.json`、
`fresh-report.md` 三份挂了一整天。**这不是用的人做错了，是这一页原来少了最后一步。**

现在多了一栏「改了什么」：列出工作区所有改动（带 `+N −N`，新文件标「新文件」），
**逐个勾**，写一句话，一次提交。三条是刻意的：

- **没有「全选」按钮。** 这一页的纪律是绝不提交不是自己改的东西，全选天生和它对着干。
- **只提交，不推送。** 上线是另一件事，不该藏在这个按钮后面。
- **署名是仓库默认的那个人，不是 bot。** `tick.sh` 那两处署 `atlas-watch[bot]`
  就是为了在 `git log` 里分得开 —— 人在台上点的这一次是人工提交。

服务端只接受**此刻真的有改动的路径**：前端传别的会被 409 挡下。
这支进程读写得到整个仓库，不校验就等于开了一个「把任意路径加进暂存区」的口子。

### 那一页上能跑的活

只跑**白名单**里的，不接受任意命令 —— 这支服务能写库能提交 git，
留一个「跑任意命令」的口子等于把整台机器挂上去，哪怕它只听 127.0.0.1。

橙色那个（**把仓库数字写回 atlas.json**）会改数据，点了要确认。
「机器不碰 atlas.json」那条纪律管的是**无人值守的定时跑**；
人在这里点写回是人自己的判断 —— 但要点得明明白白，不能和「出份报告」混在一排里顺手点掉。

⚠️ 改完 `scripts/review-ui.mjs` **必须过 `node --check`**：页面 HTML 是写在模板
字符串里的，**注释里带一个反引号就会把模板提前结束**，而报错只在浏览器控制台里 ——
页面看起来只是「一条数据都没有」。栽过一次。

⚠️ 而且 `node --check` **还不够**：页面脚本里的反斜杠要写两遍
（源码里的 `\\*` 到页面上才是 `\*`）。转义错了语法照样是对的，
只是正则悄悄变成另一个意思。**这一页必须真在浏览器里打开看过。**

## 二之三、快讯通知 —— 站上唯一会打断阅读的东西

`/changes` 页与 `changes.xml` 都是「读者主动来才看得到」，周报一周一次。
三条出口都不覆盖「**今天有一件事改变了做法，下周一才说就晚了**」。快讯补的是这一档。

### 怎么发一条

**不新建数据。** 在 `data/changes.json` 里那条变更事件上加一个字段：

```json
"breaking": { "until": "2026-09-16", "headline": "白模预演成了新的控制轴：排完再生成，不再抽卡" }
```

那份文件开头就写着「**变更事件只有这一份**」—— 一度另建过 `change_events`，
两份迟早对不上。所以快讯不是新表，是变更事件上的一个标记。
同一条事实，**页面、RSS、横幅、飞书四个出口全从它出来**。

然后在审阅台点「重算快讯横幅」看文案，确认无误再点橙色那个「把快讯推到飞书」。

### 机器替你守着的四条

`scripts/validate.mjs` 里的 R92–R99，全是「错了不会有任何物理症状」的那类 ——
横幅照样渲染、RSS 照样生成，只是内容站不住脚：

| 规则 | 守什么 |
|---|---|
| R92 / R93 | 必须有 `headline` 和 `until` |
| R94 / R96 | 必须有 `src` 和 `why` —— **横幅上没有出处，它就是一条广告** |
| R97 | 挂不过 30 天。超过一个月还要打断读者的事，说明它该进正文 |
| R99 | 同时在架不超过 3 条。**横幅一多就没人看了**，那时它比没有更糟 |

### 挂多久：**一期 = 7 天**

`until` 可以不写，不写就是「发生日 + 7 天」。上限也是 7 天（R97）。

原来是 30 天，负责人 08-19 判太久 —— 对的：挂满一个月的快讯第二周起就是背景板，
而横幅一旦被学会忽略，下一条真要紧的也一起没人看。

为什么是 7：源的 `refresh_days` 里 7 天那一档最多（448 个源里 105 个），
**一周之内这条事实多半已经被下一轮采集重新核过一遍**。

⚠️ **「一周一期数据采集」这个说法不成立。** 实际是：`tick.sh` 每天跑，
按每个源自己的 `refresh_days` 到期才抓（3 / 7 / 14 / 21 / 30 / 60 / 90 / 180 天都有）。
真正按「期」走的是**周报**，而周报只出过两期（08-07、08-09）之后就停了。
所以快讯的期限没有绑周报 —— 绑一个停着的锚，等于没绑。

### 收起与展开

右上角 `×` 收起，收起后剩一行「快讯 N 条 · 展开」。多于一条时纵向滚动，
**不做自动轮播**：轮播看着热闹，代价是读者读到一半被换走。

两种形态**都渲染进 HTML**，由 `<html>` 上的 `flash-closed` 类决定显示哪个，
类由一段同步脚本从 localStorage 读出来设上 —— 和 layout 里主题那段同一个理由：
走 React 的话每进一页都先闪一下展开再收起。

**关掉一次不等于永远闭嘴**：存的是当前这批快讯的**签名**（各条 id 拼起来），
换了新快讯签名就变，横幅自己重新展开。存布尔值的话，读者随手点一次 ×，
这条通道就对他永久失效了，而他并不知道。

### 到期自己下架

过期的 `alert.mjs` 就不把它放进 `data/alerts.json`，
横幅、RSS 的置顶与「快讯」分类一起消失。
**一个要靠人记得删的横幅，就是会挂一年的横幅** —— 而挂着的旧快讯比没有横幅更伤：
它告诉读者这个站没人管。

`prebuild` 里也挂了一次 `alert.mjs`（不带 `--push`），
所以**每次构建都会重算一遍**，不会因为很久没跑定时任务而把过期的挂上线。

### 推送要显式要

`alert.mjs` 默认**只算不推**，推要写 `--push`。
不这么分的话，本地跑一次 `npm run build` 群里就响一下 —— 而那条消息内容一模一样。
推过的记在 `data/alert-sent.json`（进 git，换台机器才不会重推一遍）。

## 三、日常怎么用

### 它会主动叫你

跑完会发一条通知，**点开就是审阅台**（没开着会自己拉起来）。
飞书群里也发一条，同样只给审阅台这一个地址。
**这是刻意做的**：管线会攒待办，但在通知做出来之前它不会叫人 ——
收件箱里 17 条从 08-07 躺到 08-11，四天没人知道，因为唯一的出口是日志文件，
而人不会每天打开日志。

### 手动跑各段

```bash
node scripts/watch.mjs --due                  # 只抓到期的
node scripts/watch.mjs --only kling-api,hf-t2v # 抓指定几个（调试用）
node scripts/requote.mjs --report             # 引文回查
node scripts/version-sentry.mjs --json        # 版本哨兵（--at <git ref> 拿历史快照跑，自检用）
node scripts/todo.mjs --notify                # 重算待办并通知
node scripts/fresh.mjs                        # 保鲜巡检（仓库数字 / README 漂移 / 外链）
node scripts/fresh.mjs repos                  # 只查其中一支
bash  scripts/tick.sh                         # 整条链跑一遍（和定时任务完全一样）
```

### 待办超过 20 条会怎样

`triage.mjs` 里有条负反馈（§59.3 的 F6）：**人每周要看的必须 ≤20**。
**连续两次**超过 20，就自动把最吵的那一类黄色规则降为绿色（自动发布）。
一次超标不触发 —— 那个两击保险是为了防止某次报告口径变化误伤采集纪律。

⚠️ **红色永远不放宽**，那批错了会污染整张图。

## 四、坏了怎么查

| 症状 | 先看哪 | 多半是 |
|---|---|---|
| 通知没来 | `tail -40 data/watch.log` | 任务没装载，或某一段报错退出 |
| 一大批源同时「抓不到」 | 代理是否开着：`curl -x http://127.0.0.1:7890 -I https://huggingface.co` | 代理没起。`tick.sh` 里写死了 `127.0.0.1:7890` |
| 某个源抓到了但没内容 | `data/watch-report.md` 的「抓到了但没内容」小节 | 那页是 SPA 壳，要把该源改成 `kind: "spa"` |
| `extract.mjs` 被跳过 | 日志里有「没有 MINIMAX_API_KEY」 | `.env` 没有 key。**采集本身不需要模型**，跳过不影响抓取 |
| git 提交失败 | `data/watch.log` 尾部 | 工作区有冲突，或仓库被别的进程占着 |

**日志在三个地方，各看各的：**

- `data/watch.log` —— 每次跑的完整过程（人看这个）
- `data/launchd.out.log` / `.err.log` —— launchd 自己的输出（任务压根没起来时看这个）
- `data/watch-report.md` —— 这一轮的源级结论（哪些变了、哪些抓不到）

## 五、曾经踩过的坑（都是真出过事的）

1. **plist 没装进 `~/Library/LaunchAgents/`，重启后不会自启**（2026-08-15 修）。
   之前是从仓库路径直接 `launchctl bootstrap` 的 —— 那样**只对当前登录会话有效**。
   任务在 `launchctl list` 里看得见，会让人以为一切正常，
   **而它其实活不过一次重启**。现在用软链装进去了。

2. **launchd 不继承登录 shell 的环境变量。** 代理、`PATH`、密钥都得在
   `tick.sh` 里显式给。密钥从仓库根的 `.env` 读（已在 `.gitignore` 里）——
   **不写进 plist**，因为 plist 要进 git。

3. **空提交会把 git log 冲成噪音。** 判断「要不要提交」的依据必须是
   **快照变没变**，不是报告变没变 —— 报告每跑一次都会带新时间戳。
   `git log` 是我们的 ChangeEvent 表，冲花了就没法回溯了。

4. **通知点开是脚本编辑器。** `osascript` 发的通知归属于「脚本编辑器」，
   点它只会打开那个 app。现在改成 `ops/虾米待办.app`（`osacompile` 生成、跟着仓库走），
   点开直接是审阅台。

   ⚠️ **而那个 app 建好之后，点下去这一路整整一段时间根本没跑通**（2026-08-18 修）。
   脚本第一句是 `if (count of argv) is 0`，用 `osascript` 跑没事，
   但 LaunchServices 启动 app 时（双击、点通知都走这条）**不传那个参数**，
   `count of argv` 当场抛 -1708，applet 一秒内退出。
   **不报错、不留日志，看起来只是「点了没反应」**，所以躺了很久没人发现。
   教训：这个 app 改完必须**用 `open` 实测**，`osascript` 跑通不算数 ——
   那个 bug 只在 `open` 这条路上才出现。

5. **盯的地址和引的地址可以不一样，但不能对不上正文**（2026-08-15 修）。
   引用表里放的是**给读者点的人读页**（`huggingface.co/xxx`），
   监视清单里放的是**给机器 diff 的地址** —— 这本身是对的。
   但有 8 个源盯的是元数据接口（`api/models`、`api.github.com/repos`），
   而格子引的是模型卡正文，**接口返回里根本没有那句话**，
   等于「引文永远无法回查、页面改了也没人知道」。
   `requote.mjs` 就是为了让这类问题以后自己冒出来。

   ⚠️ 改盯法时**要由「引用表说我们读的是哪一页」决定**，不能看仓库在哪就盯哪 ——
   我第一次改 `openvla-gh` 就指错了（引用表写的是 HF 模型卡，我指到了 GitHub README，
   两边文字并不一样）。
