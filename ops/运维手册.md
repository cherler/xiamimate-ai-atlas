# 采集链运维手册

> 这条链每天 09:23 自己跑一次。**电脑重启后它会自己回来** —— 但那是 2026-08-15
> 才修好的，在那之前不会（原因见文末「曾经踩过的坑」第 1 条）。
>
> 这份文档回答四件事：它是什么、重启后怎么办、怎么看它有没有在干活、坏了怎么修。

---

## 一、它是什么：一条链，五段

```
launchd（每天 09:23）
   └─ scripts/tick.sh
        ├─ ① watch.mjs --due      抓到期的源 → 写 data/snapshots/
        ├─ ② requote.mjs --report 回查引文 → 写 data/requote-report.md
        ├─ ③ extract.mjs          有变化才调模型 → 写 data/inbox/（唯一花钱的一步）
        ├─ ④ todo.mjs --notify    汇总成 data/TODO.md + 发通知
        └─ ⑤ git commit           署名 atlas-watch[bot]
```

**三条纪律，改任何一段都不能破：**

1. **机器只写快照、报告、收件箱，绝不碰 `data/atlas.json`。**
   「世界变了」和「我们认定它变了」是两件事，后者要人审（§59.3 的黄/红通道）。
2. **提交署名 `atlas-watch[bot]`**，在 `git log` 里和人工提交一眼分得开。
3. **失败不静默。** 抓不到、抓到空壳都进日志与报告 ——
   **一个长期抓不到的官方源本身就是信息**：那家没有可 diff 的公开入口，
   这正好解释了它名下的格子为什么质量最差。

## 二、电脑重启之后

### 正常情况：什么都不用做

plist 已软链到 `~/Library/LaunchAgents/`，登录时 launchd 会自动读它。
**笔记本合盖睡过头也不会漏**：`StartCalendarInterval` 在错过触发时间后
会在下次唤醒时补跑一次（这是当初选 launchd 而不是 crontab 的唯一理由）。

### 三十秒自检

```bash
cd ~/projects/xiamimate/xiamimate-ai-atlas

# 1. 任务在不在（有输出 = 在）
launchctl list | grep xiamimate

# 2. 上次什么时候跑的、跑成了没有
tail -20 data/watch.log

# 3. 待办有几条
head -3 data/TODO.md
```

三条都正常就不用管了。**第 1 条没输出**才需要下一节。

### 如果任务不见了

```bash
cd ~/projects/xiamimate/xiamimate-ai-atlas

# 重新装（软链 + 装载，可重复执行，装过了也不会坏）
ln -sfn "$PWD/ops/com.xiamimate.atlas-watch.plist" \
        ~/Library/LaunchAgents/com.xiamimate.atlas-watch.plist
launchctl bootout   gui/$(id -u)/com.xiamimate.atlas-watch 2>/dev/null
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.xiamimate.atlas-watch.plist

# 立刻踢一次，验证端到端能跑
launchctl kickstart -k gui/$(id -u)/com.xiamimate.atlas-watch
tail -20 data/watch.log
```

⚠️ **用软链不用复制。** 复制过去的话，以后改 plist（比如换时间）
要记得再复制一次 —— 那种「要记得」的东西迟早会忘。软链让 plist 继续跟着 git 走。

## 二之二、审阅台：**故意不做开机自启**

采集那条链是 launchd 常驻的，审阅台不是 —— 用的时候手动起：

```bash
cd ~/projects/xiamimate/xiamimate-ai-atlas
node scripts/review-ui.mjs      # → http://127.0.0.1:8230
```

**这是有意的选择（2026-08-15 负责人拍板「保持手动就好」），不是漏配。**
它和采集器不一样：**它能写 `atlas.json` 并直接提交 git**。
一个能改库的服务常驻在后台、还随开机自启，风险和收益不成正比 ——
而它一周也就用几次。

两个标签：

- **收件箱** —— 抽取器捞出来的候选事实，判断是「这条对不对」（通过 / 驳回）
- **引文回查** —— `requote.mjs` 找出的「引文和它署的源对不上」，判断是「这句该归到哪」：
  改署名 / 换这个源的抓法 / 认了它不是逐字原文

⚠️ 改完 `scripts/review-ui.mjs` **必须过 `node --check`**：页面 HTML 是写在模板
字符串里的，**注释里带一个反引号就会把模板提前结束**，而报错只在浏览器控制台里 ——
页面看起来只是「一条数据都没有」。栽过一次。

## 三、日常怎么用

### 它会主动叫你

跑完会发一条通知，点开就是 `data/TODO.md`。
**这是刻意做的**：管线会攒待办，但在通知做出来之前它不会叫人 ——
收件箱里 17 条从 08-07 躺到 08-11，四天没人知道，因为唯一的出口是日志文件，
而人不会每天打开日志。

### 手动跑各段

```bash
node scripts/watch.mjs --due                  # 只抓到期的
node scripts/watch.mjs --only kling-api,hf-t2v # 抓指定几个（调试用）
node scripts/requote.mjs --report             # 引文回查
node scripts/todo.mjs --notify                # 重算待办并通知
bash  scripts/tick.sh                         # 整条链跑一遍（和定时任务完全一样）
```

### 待办超过 20 条会怎样

`triage.mjs` 里有条负反馈（§59.3 的 F6）：**人每周要看的必须 ≤20**。
**连续两次**超过 20，就自动把最吵的那一类黄色规则降为绿色（自动发布）。
一次超标不触发 —— 那个两击保险是为了防止某次报告口径变化误伤采集纪律。

⚠️ **红色永远不放宽**，那批错了会污染整张图。

## 四、坏了怎么查

| 症状 | 先看哪 | 多半是 |
|---|---|---|
| 通知没来 | `tail -40 data/watch.log` | 任务没装载，或某一段报错退出 |
| 一大批源同时「抓不到」 | 代理是否开着：`curl -x http://127.0.0.1:7890 -I https://huggingface.co` | 代理没起。`tick.sh` 里写死了 `127.0.0.1:7890` |
| 某个源抓到了但没内容 | `data/watch-report.md` 的「抓到了但没内容」小节 | 那页是 SPA 壳，要把该源改成 `kind: "spa"` |
| `extract.mjs` 被跳过 | 日志里有「没有 MINIMAX_API_KEY」 | `.env` 没有 key。**采集本身不需要模型**，跳过不影响抓取 |
| git 提交失败 | `data/watch.log` 尾部 | 工作区有冲突，或仓库被别的进程占着 |

**日志在三个地方，各看各的：**

- `data/watch.log` —— 每次跑的完整过程（人看这个）
- `data/launchd.out.log` / `.err.log` —— launchd 自己的输出（任务压根没起来时看这个）
- `data/watch-report.md` —— 这一轮的源级结论（哪些变了、哪些抓不到）

## 五、曾经踩过的坑（都是真出过事的）

1. **plist 没装进 `~/Library/LaunchAgents/`，重启后不会自启**（2026-08-15 修）。
   之前是从仓库路径直接 `launchctl bootstrap` 的 —— 那样**只对当前登录会话有效**。
   任务在 `launchctl list` 里看得见，会让人以为一切正常，
   **而它其实活不过一次重启**。现在用软链装进去了。

2. **launchd 不继承登录 shell 的环境变量。** 代理、`PATH`、密钥都得在
   `tick.sh` 里显式给。密钥从仓库根的 `.env` 读（已在 `.gitignore` 里）——
   **不写进 plist**，因为 plist 要进 git。

3. **空提交会把 git log 冲成噪音。** 判断「要不要提交」的依据必须是
   **快照变没变**，不是报告变没变 —— 报告每跑一次都会带新时间戳。
   `git log` 是我们的 ChangeEvent 表，冲花了就没法回溯了。

4. **通知点开是脚本编辑器。** `osascript` 发的通知归属于「脚本编辑器」，
   点它只会打开那个 app。现在改成 `ops/虾米待办.app`（`osacompile` 生成、跟着仓库走），
   点开直接是 `data/TODO.md`。

5. **盯的地址和引的地址可以不一样，但不能对不上正文**（2026-08-15 修）。
   引用表里放的是**给读者点的人读页**（`huggingface.co/xxx`），
   监视清单里放的是**给机器 diff 的地址** —— 这本身是对的。
   但有 8 个源盯的是元数据接口（`api/models`、`api.github.com/repos`），
   而格子引的是模型卡正文，**接口返回里根本没有那句话**，
   等于「引文永远无法回查、页面改了也没人知道」。
   `requote.mjs` 就是为了让这类问题以后自己冒出来。

   ⚠️ 改盯法时**要由「引用表说我们读的是哪一页」决定**，不能看仓库在哪就盯哪 ——
   我第一次改 `openvla-gh` 就指错了（引用表写的是 HF 模型卡，我指到了 GitHub README，
   两边文字并不一样）。

## 六、想改点什么

| 想改 | 改哪 |
|---|---|
| 跑的时间 | `ops/com.xiamimate.atlas-watch.plist` 的 `StartCalendarInterval`，改完重新 bootstrap |
| 加/删监视源 | `data/sources.json`。⚠️ 加完跑一次 `--only 新id` 验证真能抓到 |
| 某个源多久抓一次 | 该源的 `refresh_days`（3~30 天不等，越权威越勤） |
| 待办的摞法 | `scripts/todo.mjs`。⚠️ **新加的摞要想清楚它的计数单位** —— 直接把几十条塞进去会打爆 ≤20 那条闸门 |
| 通知渠道 | `scripts/todo.mjs` 的 `--notify` 那段 |
